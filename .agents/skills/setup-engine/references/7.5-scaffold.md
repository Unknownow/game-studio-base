## 7.5 Scaffold the Engine Project

**Without this step the framework produces source files no engine can open.**
`/dev-story` writes source files under the resolved code root, and the `minimal` path
advertises "four steps to running code" — but no other skill writes the project files
an engine needs to load them.

**Never overwrite an existing engine project.** If one is already there (the engine's project marker
file exists), say so and skip to Section 8 — the developer has a project and its settings are theirs.

Engine step `hook: setup-engine/scaffold`: if `ENGINE.md` exists, follow its section `## hook: setup-engine/scaffold`; otherwise ask the user how their engine does this and record the answer in `ENGINE.md` under that heading.
The section says one of two things for the engine:

- **A project file this skill can write.** Show the proposed file, ask "May I create [path]?", write it
  from decisions already made (do not ask again), then verify it and report what the verification
  actually was. If the engine binary was not found in Section 3, or its version differs from the pinned
  one, write **`<file> NOT VERIFIED — <reason>`**: "stable in the versions I know" is not the same as
  "checked against the version you pinned", and only a run establishes the latter.
- **A project the editor must create.** Editor-generated projects span many files, several binary or
  machine-specific. This repo cannot source their correct contents, and a hand-written scaffold would be
  the exact failure Section 7's sourcing rule forbids: something that looks finished and is quietly
  wrong. Tell the user, in one short block, that the framework does not create the project for this
  engine and they should create it first, then re-run `/setup-engine`.

Report the outcome in the Section 12 summary either way — created, already present, or "not created,
engine requires the editor" — so the user leaves this skill knowing whether a runnable project exists.

> **Deliberately not a `project.toml` key.** A "project scaffolded" flag would be written here and
> read by nothing, which is a dead setting. The filesystem is the source of truth: any skill that needs
> to know checks for the engine's project marker file (`project_marker` in `engine.toml`).
